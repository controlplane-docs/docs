## Overview

OpenSearch is an open-source distributed search and analytics engine for full-text search, log analytics and security monitoring. This template deploys a multi-node OpenSearch cluster with the security plugin always on: a login, TLS on every connection, and a security audit log. Security Analytics (Sigma-rule detectors, findings and alerts) is included, so the cluster doubles as a self-hosted SIEM; see also the [Wazuh](/template-catalog/templates/wazuh) template for endpoint security. Dashboards is on by default, with an optional public login page, an optional demo log pipeline with a sample detector, and optional snapshots to AWS S3 or GCS.

<Note>
This template deploys into an existing [GVC](/reference/gvc) that you already have. It does not create one, and it runs in the locations that GVC already has.
</Note>

## Prerequisites

Two dictionary secrets must exist before you install.

<Steps>
  <Step title="Create the credentials secret">
    It holds the `admin` password, the password Dashboards uses to reach OpenSearch, and the Dashboards session-cookie key (32 or more characters).

    ```bash
    cpln secret create-dictionary --name CREDENTIALS_SECRET_NAME \
      --entry password="$(openssl rand -hex 16)" \
      --entry dashboardsPassword="$(openssl rand -hex 16)" \
      --entry cookieSecret="$(openssl rand -hex 32)"
    ```

    Set `security.credentialsSecretName` to this name. Read the admin password back with `cpln secret reveal CREDENTIALS_SECRET_NAME -o yaml`.
  </Step>
  <Step title="Create the certificate authority secret">
    The nodes sign their own certificates from a CA you provide, stored as a base64 PKCS#12 plus its passphrase.

    ```bash
    openssl req -x509 -newkey rsa:3072 -nodes -keyout ca.key -out ca.crt -days 3650 -subj "/CN=opensearch-ca" \
      -addext "basicConstraints=critical,CA:TRUE" -addext "keyUsage=critical,keyCertSign,cRLSign"
    P="$(openssl rand -hex 16)"
    openssl pkcs12 -export -inkey ca.key -in ca.crt -out ca.p12 -passout pass:"$P"
    cpln secret create-dictionary --name CA_SECRET_NAME \
      --entry keystore="$(base64 < ca.p12 | tr -d '\n')" --entry passphrase="$P"
    ```

    Set `security.caSecretName` to this name. Keep `ca.crt`: your applications use it to verify the cluster's certificate. Store `ca.key` safely or delete it; the secret already holds the key.
  </Step>
</Steps>

<Warning>
If either secret is missing, the deployment wedges silently: the nodes never start and `cpln logs` shows nothing. The missing secret is named only in `status.versions[].message`, which you read with `cpln workload get-deployments RELEASE_NAME-opensearch --gvc GVC_NAME -o yaml`.
</Warning>

Snapshot backups also need a bucket and a Control Plane Cloud Account. See [Backing Up](#backing-up).

## Configuration

Each subsection shows the shipped defaults for one area of `values.yaml`.

### Cluster

`replicas` must be odd so the cluster can form a quorum; an even value is rejected when the chart renders.

```yaml
image: opensearchproject/opensearch:3.8.0

replicas: 3 # Must be odd

clusterName: my-opensearch-cluster
```

### Resources

Per-node limits and reservations. OpenSearch is memory-sensitive; raise `maxMemory` before raising CPU.

```yaml
resources:
  minCpu: 500m
  minMemory: 2Gi
  maxCpu: 1
  maxMemory: 4Gi
```

### Volume Set

One volume per node. Enable autoscaling to let each volume grow as indices fill it.

```yaml
volumeset:
  capacity: 10 # initial capacity in GiB (minimum is 10)
  autoscaling:
    enabled: false # Set to true to enable autoscaling
    maxCapacity: 100 # Maximum capacity in GiB when autoscaling is enabled
    minFreePercentage: 10 # Minimum free percentage to trigger scaling when autoscaling is enabled
    scalingFactor: 1.2 # Scaling factor to determine how much to scale up when autoscaling is triggered
```

### Security

The two [prerequisite secrets](#prerequisites). Both are required; the chart refuses to render without them.

```yaml
security:
  credentialsSecretName: my-opensearch-credentials # dictionary: password (admin), dashboardsPassword (kibanaserver), cookieSecret (32+ chars)
  caSecretName: my-opensearch-ca # dictionary: keystore (base64 PKCS#12 with the CA certificate and key), passphrase
```

### Internal Access

Controls which workloads may reach OpenSearch on port `9200`. External inbound access is closed and is not configurable. Every request still needs credentials.

```yaml
internal_access:
  type: same-gvc # options: same-gvc, same-org, workload-list
  workloads:  # Note: can only be used if type is same-gvc or workload-list
    #- //gvc/GVC_NAME/workload/WORKLOAD_NAME
    #- //gvc/GVC_NAME/workload/WORKLOAD_NAME
```

| Type | Who can connect |
|---|---|
| `same-gvc` | Every workload in the same GVC |
| `same-org` | Every workload in the same org |
| `workload-list` | The workloads listed under `workloads`, plus the chart's own workloads |

With `workload-list`, list your additional clients only; the chart always allows its own workloads (the nodes, Dashboards, the demo and backup jobs).

### Dashboards

The OpenSearch Dashboards UI, with a login. It is private by default; reach it with `cpln port-forward` as shown in [Connecting](#connecting). Set `publicAccess.enabled: true` to publish the login page on an HTTPS `*.cpln.app` endpoint.

```yaml
dashboard:
  enabled: true
  image: opensearchproject/opensearch-dashboards:3.8.0
  resources:
    cpu: 250m
    memory: 1Gi
  publicAccess:
    enabled: false # true publishes the login page on an HTTPS *.cpln.app endpoint
```

### Demo Logs

A sample log generator with a Fluent Bit sidecar that ships JSON logs into a `demo-logs` index, plus a one-time setup job that creates the index template, makes `demo-logs*` the default index pattern in Dashboards, and creates a sample Security Analytics detector. The setup job needs `dashboard.enabled: true`.

```yaml
demoLogs:
  enabled: false
  remove_setup_workload: false # Set to true after demo logs startup is no longer needed to reduce resource usage
```

### Backup

Scheduled snapshots to AWS S3 or GCS. Complete the provider steps in [Backing Up](#backing-up) before setting `enabled: true`. When `provider` is `aws`, `aws.bucket`, `aws.region`, `aws.cloudAccountName` and `aws.policyName` are required; when it is `gcp`, `gcp.bucket` and `gcp.cloudAccountName` are required. Any other `provider` value is rejected when the chart renders.

```yaml
backup:
  enabled: false      # Set to true to enable automated snapshots
  remove_setup_workload: false # Set to true after backup setup is no longer needed to reduce resource usage

  # Cloud provider: aws or gcp
  provider: aws

  # Backup schedule (cron format, UTC timezone)
  schedule: 0 2 * * *  # Daily at 2am UTC

  # Snapshot retention
  retention:
    maxAge: 30d        # Delete snapshots older than 30 days
    maxCount: 30       # Keep maximum 30 snapshots

  # AWS S3 Configuration
  aws:
    bucket: my-s3-bucket                 # S3 bucket name (required if provider=aws)
    region: us-east-1                    # S3 bucket region (required if provider=aws)
    prefix: opensearch-snapshots         # Path prefix in bucket
    cloudAccountName: my-cloud-account   # Control Plane Cloud Account name (required)
    policyName: my-backup-policy         # AWS IAM custom policy name (required)

  # GCP GCS Configuration
  gcp:
    bucket: my-gcs-bucket                # GCS bucket name (required if provider=gcp)
    prefix: opensearch-snapshots         # Path prefix in bucket
    cloudAccountName: my-cloud-account   # Control Plane Cloud Account name (required)
```

## Connecting

| What | Address | Notes |
|---|---|---|
| OpenSearch API (from workloads in the GVC) | `https://RELEASE_NAME-opensearch.GVC_NAME.cpln.local:9200` | HTTPS only; plain HTTP is refused. Subject to `internal_access` |
| Dashboards UI (private) | `cpln port-forward RELEASE_NAME-opensearch-dashboard 5601:5601 --gvc GVC_NAME`, then `http://localhost:5601` | Only when `dashboard.enabled: true` |
| Dashboards UI (public) | `status.canonicalEndpoint` of `RELEASE_NAME-opensearch-dashboard` | Only with `dashboard.publicAccess.enabled: true`; read it with `cpln workload get RELEASE_NAME-opensearch-dashboard --gvc GVC_NAME -o yaml` |
| Credentials | User `admin`, password from the `password` key of your credentials secret | `cpln secret reveal CREDENTIALS_SECRET_NAME -o yaml` |
| CA certificate | `ca.crt` from the prerequisite step | Clients pin it to verify the cluster certificate |

Verify the cluster from any workload in the same GVC, with `ca.crt` available there:

```bash
curl --cacert ca.crt -u "admin:ADMIN_PASSWORD" "https://RELEASE_NAME-opensearch.GVC_NAME.cpln.local:9200/_cluster/health?pretty"
```

A healthy default install reports `"status" : "green"` and `"number_of_nodes" : 3`.

### First Run

In Dashboards, log in as `admin` with the password from your credentials secret. Dashboards opens in the **Global** tenant, where saved objects are shared with other users; change the default under **Security > Tenants > Configure**.

### Using Security Analytics

Security Analytics runs Sigma rules over your log indices and records findings and alerts.

1. Ship logs into an index (Fluent Bit, Logstash, OpenTelemetry or the bulk API).
2. In Dashboards, open **Security Analytics > Detectors > Create detector**, choose the index and a log type (CloudTrail, VPC Flow, DNS, Windows and others ship with prepackaged rules), and map the fields it asks for.
3. Findings appear under **Findings**; add a trigger with a notification channel to be alerted.

With `demoLogs.enabled: true`, the detector `demo-auth-failures` watches the `demo-logs` index for `Invalid authentication token` messages and produces findings from the generated logs.

## Operations

### Backing Up

The template takes snapshots with OpenSearch's own snapshot API. When `backup.enabled: true`, each node installs the `repository-s3` or `repository-gcs` plugin at startup, and the `RELEASE_NAME-backup-setup` job registers a snapshot repository named `backup-repo` plus a snapshot policy that follows `backup.schedule` and `backup.retention`.

<Tip>
Enable backups at install time if you can. Turning them on later works, but every node has to restart to install the repository plugin before the repository can be registered. See [Troubleshooting](#troubleshooting).
</Tip>

Set up your provider first.

<Tabs>
  <Tab title="AWS S3">
    <Steps>
      <Step title="Create the bucket">
        Create an S3 bucket. Set `backup.aws.bucket` to its name and `backup.aws.region` to its region.
      </Step>
      <Step title="Create or choose a Cloud Account">
        If you do not have one, follow [Create a Cloud Account](/guides/create-cloud-account). Set `backup.aws.cloudAccountName` to its name.
      </Step>
      <Step title="Create the IAM policy">
        Create an IAM policy with the following JSON, replacing `YOUR_BUCKET_NAME`. Set `backup.aws.policyName` to the policy's name.

        ```json
        {
            "Version": "2012-10-17",
            "Statement": [
                {
                    "Effect": "Allow",
                    "Action": [
                        "s3:GetObject",
                        "s3:PutObject",
                        "s3:DeleteObject",
                        "s3:ListBucket",
                        "s3:GetBucketLocation",
                        "s3:ListBucketMultipartUploads",
                        "s3:AbortMultipartUpload",
                        "s3:ListMultipartUploadParts"
                    ],
                    "Resource": [
                        "arn:aws:s3:::YOUR_BUCKET_NAME",
                        "arn:aws:s3:::YOUR_BUCKET_NAME/*"
                    ]
                }
            ]
        }
        ```

        Keep both `Resource` ARNs: listing authorizes against the bucket, object actions against `YOUR_BUCKET_NAME/*`.
      </Step>
      <Step title="Enable backups">
        Set `backup.enabled: true` and `backup.provider: aws`, then install or upgrade the release.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Google Cloud Storage">
    <Steps>
      <Step title="Create the bucket">
        Create a GCS bucket. Set `backup.gcp.bucket` to its name.
      </Step>
      <Step title="Create or choose a Cloud Account">
        If you do not have one, follow [Create a Cloud Account](/guides/create-cloud-account). Set `backup.gcp.cloudAccountName` to its name.
      </Step>
      <Step title="Grant storage access">
        Add the **Storage Admin** role to the GCP service account associated with the Cloud Account. Access is keyless; no credentials are stored in the template.
      </Step>
      <Step title="Enable backups">
        Set `backup.enabled: true` and `backup.provider: gcp`, then install or upgrade the release.
      </Step>
    </Steps>
  </Tab>
</Tabs>

Check that the setup job finished by reading its logs:

```bash
cpln logs '{gvc="GVC_NAME", workload="RELEASE_NAME-backup-setup"}' --limit 50 --since 10m
```

Once it has completed, set `backup.remove_setup_workload: true` and upgrade the release to remove the setup workload. Scheduled snapshots continue without it.

From a workload in the same GVC, set `OS=https://RELEASE_NAME-opensearch.GVC_NAME.cpln.local:9200` and `AUTH="admin:ADMIN_PASSWORD"`, then take or inspect snapshots:

```bash
# Take a manual snapshot
curl --cacert ca.crt -u "$AUTH" -X PUT "$OS/_snapshot/backup-repo/manual-$(date +%Y%m%d-%H%M%S)"

# List all snapshots
curl --cacert ca.crt -u "$AUTH" "$OS/_snapshot/backup-repo/_all?pretty"
```

### Restoring a Backup

OpenSearch snapshots are raw index segment files, not dumps; restore them through the snapshot API from the `backup-repo` repository, using `OS` and `AUTH` as above. Always leave out `.opendistro_security`: it holds the live users and roles.

**Into an empty cluster** — nothing to conflict with:

```bash
curl --cacert ca.crt -u "$AUTH" -X POST "$OS/_snapshot/backup-repo/SNAPSHOT_NAME/_restore" \
  -H 'Content-Type: application/json' \
  -d '{"indices": "*,-.opendistro_security", "ignore_unavailable": true, "include_global_state": false}'
```

**Over existing indices** — an open index cannot be restored into, so close the indices you restore first, restore, then reopen. Never close `_all`: that closes the security index and locks everyone out.

```bash
curl --cacert ca.crt -u "$AUTH" -X POST "$OS/INDEX_NAME/_close"
curl --cacert ca.crt -u "$AUTH" -X POST "$OS/_snapshot/backup-repo/SNAPSHOT_NAME/_restore" \
  -H 'Content-Type: application/json' \
  -d '{"indices": "INDEX_NAME", "ignore_unavailable": true, "include_global_state": false}'
curl --cacert ca.crt -u "$AUTH" -X POST "$OS/INDEX_NAME/_open"
```

**Alongside existing indices** — restore under new names and leave live data untouched. This is the safest option on a cluster in use:

```bash
curl --cacert ca.crt -u "$AUTH" -X POST "$OS/_snapshot/backup-repo/SNAPSHOT_NAME/_restore" \
  -H 'Content-Type: application/json' \
  -d '{"indices": "*,-.opendistro_security", "rename_pattern": "(.+)", "rename_replacement": "restored-$1",
       "ignore_unavailable": true, "include_global_state": false}'
```

Watch progress with `curl --cacert ca.crt -u "$AUTH" "$OS/_cat/recovery?v&active_only=true"`.

To restore from Dashboards Snapshot Management, pick specific indices, choose a prefix or regex rename (**Do not rename** still adds `restored_`), and uncheck **Restore cluster state** under **Advanced options**; with security on, restoring cluster state or system indices is refused. **Take snapshot** snapshots every index whatever you select; use a snapshot policy to snapshot chosen indices.

### Upgrading from 1.0.x

Version 2.0.0 turns the security plugin on, so every client changes. Your indices are kept.

<Warning>
**If you ran 1.0.0 or 1.0.1 with `demoLogs.enabled: true`, treat every secret in that organization as having been readable.** The demo-logs policy in those versions granted `reveal` on every secret in the org. Upgrading removes the grant but does not undo past access: review what the organization holds and rotate anything sensitive.
</Warning>

1. Create both [prerequisite secrets](#prerequisites).
2. Run `cpln helm upgrade` to 2.0.0 with `security.credentialsSecretName` and `security.caSecretName` set:

   ```bash
   cpln helm upgrade RELEASE_NAME oci://ghcr.io/controlplane-com/templates/opensearch \
     --version 2.0.0 --gvc GVC_NAME \
     --set security.credentialsSecretName=CREDENTIALS_SECRET_NAME \
     --set security.caSecretName=CA_SECRET_NAME
   ```

   The nodes restart one at a time. Old and new nodes cannot talk to each other, so the API is unavailable while the first nodes come up on TLS, and plain-HTTP clients fail from the first restart.
3. Point every client at `https://`, log in as `admin` (or a user you create), and trust `ca.crt`.
4. Saved objects from 1.0.x are in the **Global** tenant of Dashboards.

If a node or Dashboards is still waiting several minutes after the upgrade, run `cpln workload force-redeployment WORKLOAD_NAME --gvc GVC_NAME`: new identities and grants can take a few minutes to apply.

### Rotating Passwords

The `admin` and `kibanaserver` passwords come from the credentials secret at every node start. Change the value in the secret:

```bash
cpln secret reveal CREDENTIALS_SECRET_NAME -o yaml > secret.yaml
# edit only the key you are rotating in secret.yaml
cpln apply -f secret.yaml
cpln secret reveal CREDENTIALS_SECRET_NAME -o yaml
```

Then force a redeployment of every workload that uses it:

```bash
cpln workload force-redeployment RELEASE_NAME-opensearch --gvc GVC_NAME
cpln workload force-redeployment RELEASE_NAME-opensearch-dashboard --gvc GVC_NAME
```

With the demo pipeline on, also redeploy `RELEASE_NAME-demo-log-generator`. The nodes restart one at a time; wait for the roll to finish before assuming every node has the new password.

### Scaling and Availability

- **Cluster size.** `replicas` sets the number of OpenSearch nodes and must be odd. Three nodes is the smallest size that tolerates the loss of one node.
- **Per-node resources.** `resources.maxMemory` is the first knob to raise as index volume grows.
- **Storage.** Set `volumeset.capacity` for the data you expect, or enable `volumeset.autoscaling` so each node's volume grows as it fills. Volumes cannot shrink.
- **Rolling restarts.** The nodes restart one at a time, and reads and writes continue through a rolling restart of a three-node cluster.
- **Audit and finding indices have no retention policy.** Add an Index State Management policy if volume is high.

### Troubleshooting

<AccordionGroup>
  <Accordion title="Nodes never start and the logs are empty">
    **Cause:** A prerequisite secret is missing.

    **Fix:** Read the reason from the deployment status, create the secret it names, then wait for the rollout:

    ```bash
    cpln workload get-deployments RELEASE_NAME-opensearch --gvc GVC_NAME -o yaml
    ```
  </Accordion>
  <Accordion title="curl reports an empty reply or 'curl: (52)' against a plain HTTP URL">
    **Cause:** The API only speaks HTTPS.

    **Fix:** Use `https://` with `--cacert ca.crt` and the `admin` credentials.
  </Accordion>
  <Accordion title="curl reports 'SSL certificate problem' (curl: (60))">
    **Cause:** The client does not trust the cluster's certificate authority.

    **Fix:** Pass the `ca.crt` from the prerequisite step with `--cacert ca.crt`, or add it to the client's trust store.
  </Accordion>
  <Accordion title="A password changed in Dashboards stops working after a restart">
    **Cause:** The credentials secret is the source of truth for `admin` and `kibanaserver` and is re-applied at every node start.

    **Fix:** Change the password in the secret and redeploy, as in [Rotating Passwords](#rotating-passwords).
  </Accordion>
  <Accordion title="Backup setup logs 'repository type [s3] does not exist' (or [gcs]) and restarts">
    **Cause:** `backup.enabled` was turned on for a cluster that was already running. The repository plugin is installed by each node's startup script, so the repository cannot be registered until every node has restarted with the plugin present. The setup job retries until that happens.

    **Fix:** Wait. The job converges on its own once all nodes carry the plugin. Check progress with:

    ```bash
    cpln logs '{gvc="GVC_NAME", workload="RELEASE_NAME-backup-setup"}' --limit 50 --since 10m
    ```
  </Accordion>
  <Accordion title="Repository registers, but listing or taking snapshots fails with an S3 access-denied error">
    **Cause:** The IAM policy grants object actions on `arn:aws:s3:::YOUR_BUCKET_NAME/*` only. `s3:ListBucket` and `s3:GetBucketLocation` authorize against the bucket ARN itself.

    **Fix:** Add `arn:aws:s3:::YOUR_BUCKET_NAME` to the policy's `Resource` list, as shown in [Backing Up](#backing-up).
  </Accordion>
  <Accordion title="Applications report 'could not resolve host' for the OpenSearch workload">
    **Cause:** The application is using the bare workload name. The short name is not reliably resolvable.

    **Fix:** Use the fully-qualified hostname `RELEASE_NAME-opensearch.GVC_NAME.cpln.local:9200`, and confirm the calling workload is admitted by `internal_access`.
  </Accordion>
  <Accordion title="The demo setup job waits on 'Waiting for Dashboard...' and eventually exits">
    **Cause:** `demoLogs.enabled: true` with `dashboard.enabled: false`. The demo setup job creates the `demo-logs*` index pattern in Dashboards and cannot complete without it.

    **Fix:** Set `dashboard.enabled: true` and upgrade the release, or disable the demo pipeline.
  </Accordion>
  <Accordion title="Create correlation rule or Add threat intel source does nothing in Dashboards">
    **Cause:** In OpenSearch 3.8.0 Dashboards the **Create correlation rule** form and **Add threat intel source** with a local file do nothing.

    **Fix:** Create them through the API. Correlation rules: `POST _plugins/_security_analytics/correlation/rules`. Threat intel sources: `POST _plugins/_security_analytics/threat_intel/sources` with `"type": "IOC_UPLOAD"` and `"enabled": false` (an uploaded list is not refreshed on a schedule). Both then appear in Dashboards. An uploaded list matches nothing until a threat intel monitor scans for it: `POST _plugins/_security_analytics/threat_intel/monitors` with `per_ioc_type_scan_input_list` (for example `ioc_type: ipv4-addr` and `index_to_fields_map` from your index to its IP field) and a trigger whose `data_sources` names the source. Matches appear under **Findings > Threat intel**.
  </Accordion>
</AccordionGroup>

## Important Notes

- **Both prerequisite secrets must exist before install.** A missing one leaves the nodes waiting with nothing in the logs; `status.versions[].message` names it.
- **Rotate passwords through the credentials secret**, then run `cpln workload force-redeployment` on the workloads that use it. See [Rotating Passwords](#rotating-passwords). Use a strong, generated password.
- **Changing the CA restarts the whole cluster.** Old and new certificates do not trust each other, so the cluster is unavailable until every node has restarted with the new CA.
- **`replicas` must be odd.** An even count cannot form a quorum and is rejected when the chart renders.
- **Turn backups on at install time where you can.** On a running cluster, every node has to restart before the repository can be registered.
- **Switching `backup.provider` on an existing release leaves the old cloud binding attached.** Uninstall and reinstall if you need it gone; take a snapshot first.
- **Always leave `.opendistro_security` out of restores** and never close `_all`.
- **Use the fully-qualified internal hostname** `RELEASE_NAME-opensearch.GVC_NAME.cpln.local:9200`; the bare workload name is not reliably resolvable.
- **`cpln helm uninstall` deletes the volume sets.** Data survives a `cpln helm upgrade` but not an uninstall; enable snapshots to a bucket if the data matters.
