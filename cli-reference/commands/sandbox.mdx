Manage sandboxes

For a detailed overview, please visit the [sandbox's](/reference/sandbox/general) reference page.



```none
cpln sandbox [SUBCOMMAND]
```

<Note>

The `cpln sandbox` commands find the org's sandbox GVC themselves, so `--gvc` is not needed. A GVC named by `--gvc`, the `CPLN_GVC` environment variable, or your profile is used as given.

</Note>


```text
Commands:
  cpln sandbox access-report <ref>  Show the access report for the referenced sandbox
  cpln sandbox audit <ref>          Retrieve audit trail events for the referenced sandbox
  cpln sandbox connect <ref>        Connect to a dev sandbox: its IDE, terminal, or SSH
  cpln sandbox create <ref>         Create a new sandbox
  cpln sandbox delete <ref...>      Delete one or more referenced sandboxes and their home volumes
  cpln sandbox edit <ref>           Edit the referenced sandbox, as YAML, within an editor
  cpln sandbox eventlog <ref>       Show the event log of the referenced sandbox  [aliases: log]
  cpln sandbox get [ref...]         Retrieve one or more referenced sandboxes
  cpln sandbox patch <ref>          Update the referenced sandbox's metadata using an input file
  cpln sandbox permissions          Show the grantable permissions for a sandbox object type
  cpln sandbox session              Manage the sessions of a worker sandbox
  cpln sandbox start <ref...>       Start one or more stopped sandboxes
  cpln sandbox stop <ref...>        Stop one or more sandboxes until they are started; their home volumes are kept
  cpln sandbox tag <ref...>         Manage the tags belonging to one or more referenced sandboxes
  cpln sandbox update <ref>         Update properties of the referenced sandbox

Options:
  --help  Show help  [boolean]
```

#### sandbox create


Create a new sandbox



**Usage**

```none
cpln sandbox create <ref> [OPTIONS]
```

<Tip>

`--type dev`, the default, creates a [dev sandbox](/guides/sandbox/dev-sandbox): an IDE you sign in to. `--type worker` creates an [agent sandbox](/guides/sandbox/agent-sandbox), which holds the [sessions](#sandbox-session) that run commands.

</Tip>


<Accordion title="Reference">

```text
Positionals:
  ref  The resource reference. Usually it is the name of the resource.  [required]

Command options:
  --type                 Sandbox type: dev (an IDE you sign in to) or worker (holds sessions that run commands).  [choices: "dev", "worker"] [default: "dev"]
  --identity             The identity the sandbox runs as: one in the sandbox's GVC.
  --image                The container image the sandbox runs, or //sandboximage/<name> for a ready dev sandbox image of this org, which resolves to its built image. Defaults to the type's standard image.
  --initial-capacity     Home volume capacity in GB, 10 or more. Defaults to the server default.  [number]
  --cpu                  CPU cores to allocate. Defaults to the server default.
  --memory, --mem        Memory to allocate. Defaults to the server default.
  --app-port             The port the application inside the sandbox listens on, served at the endpoint root.  [number]
  --scale-to-zero-delay  Idle seconds (30 to 3600) before the sandbox scales to zero; the next request wakes it.  [number]
  --max-sessions         Worker sandboxes only: the sessions one worker sandbox of the identity holds at most.  [number]
  --min-workers          Worker sandboxes only: the worker sandboxes kept for the identity, this one included.  [number]
  --max-workers          Worker sandboxes only: the worker sandboxes the identity grows to at most, this one included.  [number]
  --idle-delete-delay    Worker sandboxes only: seconds a worker sandbox the server added for the identity stays empty before it is deleted.  [number]
  --env                  Environment variables for the sandbox container (e.g., --env NAME=value).

Context options:
  --profile  Override the profile. The default profile can be set using the `cpln profile set-default` command or by setting the CPLN_PROFILE environment variable
  --org      Override the organization. The default organization can be set in your profile by using the `cpln profile update` command
  --gvc      Override the global virtual cloud. The default global virtual cloud can be set in your profile by using the `cpln profile update` command

Format options:
  --output, -o  Set the output format  [choices: "text", "json", "yaml", "json-slim", "yaml-slim", "tf", "crd", "names"]
  --color       Colorize the output  [boolean] [default: true]
  --ts          Timestamp format if the output format is text (e.g., --output=text)  [choices: "iso", "local", "age"]
  --max         Maximum number of records to show. A value less than 1 will return all records.  [number] [default: 50]

Request options:
  --token         Override the authorization token
  --endpoint      Override the API URL
  --insecure, -k  Ignore TLS errors  [boolean]

Debug options:
  --verbose, -v  Enable verbose output to stderr  [boolean] [default: false]
  --debug, -d    Show all HTTP communications  [boolean] [default: false]

Options:
  --help  Show help  [boolean]
```

[Common Options Reference](/cli-reference/using-cli/common-options)

</Accordion>

<Accordion title="Options">

- `type`
  - Choices: `dev`, `worker`
  - Default: `dev`
- `cpu`
  - Type: string
  - Default: `1000m` for a dev sandbox, `4000m` for a worker sandbox
- `memory`
  - Type: string
  - Default: `2Gi` for a dev sandbox, `8Gi` for a worker sandbox
- `initial-capacity`
  - Type: number (GB)
  - Default: 20
  - Minimum Value: 10
  - Cannot be changed after the sandbox is created
- `app-port`
  - Type: number
  - Default: 8080
  - Ports 22, 7681, 8443, 8888, 49983, and 49984 are reserved
- `scale-to-zero-delay`
  - Type: number (seconds)
  - Default: 300
  - Minimum Value: 30
  - Maximum Value: 3600
- `max-sessions`
  - Worker sandboxes only
  - Type: number
  - Default: 20
  - Minimum Value: 1
  - Maximum Value: 500
- `min-workers`
  - Worker sandboxes only
  - Type: number
  - Default: 1
  - Minimum Value: 1
  - Maximum Value: 100
- `max-workers`
  - Worker sandboxes only
  - Type: number
  - Default: 10
  - Minimum Value: 1
  - Maximum Value: 100
  - Must be at least `min-workers`
- `idle-delete-delay`
  - Worker sandboxes only
  - Type: number (seconds)
  - Default: 3600
  - Minimum Value: 300
  - Maximum Value: 604800


</Accordion>

  - `spec.containers.<name>.image`
    - The container image the sandbox runs
    - Type: string
  - `spec.containers.<name>.cpu`
    - The amount of cpu units available to the sandbox
    - Type: string
  - `spec.containers.<name>.memory`
    - The amount of memory available to the sandbox
    - Type: string
  - `spec.containers.<name>.env.<name>.value`
    - The environment variables to be available to the sandbox container
    - Type: string
  - `spec.sandbox.appPort`
    - The port the application inside the sandbox listens on
    - Default: 8080
    - Type: number
  - `spec.sandbox.scaleToZeroDelay`
    - Idle seconds (30 to 3600) before the sandbox scales to zero
    - Default: 300
    - Type: number
  - `spec.sandbox.scaling.maxSessions`
    - Worker sandboxes only: the sessions (1 to 500) one worker sandbox holds at most
    - Default: 20
    - Type: number
  - `spec.sandbox.scaling.minWorkers`
    - Worker sandboxes only: the worker sandboxes (1 to 100) kept for the identity
    - Default: 1
    - Type: number
  - `spec.sandbox.scaling.maxWorkers`
    - Worker sandboxes only: the worker sandboxes (1 to 100) the identity grows to at most
    - Default: 10
    - Type: number
  - `spec.sandbox.scaling.idleDeleteDelay`
    - Worker sandboxes only: seconds (300 to 604800) a worker sandbox the server added stays empty before it is deleted
    - Default: 3600
    - Type: number
