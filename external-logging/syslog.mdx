## Overview

[Syslog](https://www.rfc-editor.org/rfc/rfc3164) is a protocol used for sending and storing log messages across networked devices and systems.

With Syslog, you can collect and analyze log messages, monitor system and network activity, set up centralized log management, and automate responses to critical events. This enhances operational visibility and ensures the reliability and stability of your applications and infrastructure.

Follow the steps below to configure log shipping to Syslog.

## Step 1 - Prerequisites

- **Syslog Endpoint**: A reachable hostname for your Syslog server.
- **Port**: Standard Syslog uses port `514`. Use the port your server listens on for the selected mode.

## Step 2 - Configure External Logging

External logging can be configured by using either the [UI Console](#enable-logging-using-the-ui-console) or [CLI](#enable-logging-using-the-cli).

### Enable Logging using the UI Console

1. From the Control Plane Console UI, click on `Org` in the left menu.
2. Click `External Logs` in the middle context menu.
3. Select `Syslog` and fill out the required fields.
4. Click `Save`.
5. After the configuration is complete, log entries will begin forwarding to your Syslog Server within a few minutes.

### Enable Logging using the CLI

The external logging configuration can be created / updated using the CLI's `cpln org patch ORG_NAME -f FILE.yaml` command.

Below is an example of an [Org](/reference/org) manifest (in YAML). Edit and save the YAML as a file and use it as an input to the CLI's `cpln org patch ORG_NAME -f FILE.yaml` command.


- Substitute: ORG_NAME, HOST_NAME, PORT, and possibly the mode, format, and severity.

```yaml YAML
kind: org
name: ORG_NAME
spec:
  logging:
    syslog:
      format: rfc5424
      host: HOST_NAME
      mode: tcp
      port: PORT
      severity: 6
```


## Configuration Fields

| Field | Description | Values |
| --- | --- | --- |
| `host` | Hostname of the syslog server. Required. | |
| `port` | Port of the syslog server. Required. | A positive integer. |
| `mode` | Transport used to send messages. Required. | `tcp`, `udp`, or `tls` |
| `format` | Syslog message format. Required. | `rfc5424` or `rfc3164` |
| `severity` | Syslog severity assigned to every forwarded message. Required. | `0` Emergency, `1` Alert, `2` Critical, `3` Error, `4` Warning, `5` Notice, `6` Informational, `7` Debug |

In the Console, `mode`, `format`, and `severity` are pre-filled with `tcp`, `rfc3164`, and `6`. A manifest must set all of them.

The `gvc` is sent as the hostname, the `workload` as the application name, the `replica` as the process ID, and the log line as the message.

## Message Size Limits

Messages larger than the limit are truncated. The limit applies to the whole syslog message, including the header, and depends on the format. It is the same for `tcp`, `udp`, and `tls`.

| Format | Maximum message size |
| --- | --- |
| `rfc3164` | 1024 bytes |
| `rfc5424` | 32 KiB (32768 bytes) |

<Note>
Very long container log lines may already be split into several log entries by the container runtime before they are forwarded. Each entry is sent as a separate syslog message.
</Note>

<Note>
With `udp`, each message is sent as a single datagram. Large datagrams may be fragmented on the network, and a lost fragment drops the whole message. Use `tcp` or `tls` if you need large messages delivered reliably.
</Note>
