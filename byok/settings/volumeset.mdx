When using a volume set in a BYOK environment, there are some additional configuration settings available.

## Storage Class Suffix

You can specify a `spec.storageClassSuffix` in a volume set. When this property is set, Control Plane will look for a storage class including this suffix. Storage classes are constructed by combining `spec.performanceClass`, `spec.fileSystemType`, and (optionally) the `spec.storageClassSuffix`. If a storage class including the suffix cannot be found, Control Plane falls back to the storage class excluding the suffix. This allows BYOK users to utilize any CSI-compatible storage solution they wish.

## Shared File System

A volume set with `fileSystemType: shared` stores its data with [JuiceFS](https://juicefs.com): file data goes to an object storage bucket, and file metadata goes to a metadata engine. On cloud locations, Control Plane sets both up. On a BYOK location, you set them up once per cluster, and then shared volume sets work like they do anywhere else.

Until the setup is done, a shared volume set gets no volume in that location, and the actuator logs `JuiceFS configmap "juicefs" not found in namespace "controlplane". Shared filesystem volumes are not available.`

### 1. Install the JuiceFS CSI driver

Set `juicefs.enabled` to `true` in the cluster's [agent settings](/byok/settings/agent#juicefs). That installs the JuiceFS CSI driver (`csi.juicefs.com`) and a Redis Sentinel, `juicefs-redis`, that you can use as the metadata engine, both in the `juicefs` namespace.

- **Kubernetes cluster not managed by Control Plane:** add `"juicefs": {"enabled": true}` to the `cpln-byok-current` configmap in the `kube-system` namespace.
- **[Managed Kubernetes](/mk8s/add-ons/byok) cluster:** set `spec.addOns.byok.config.juicefs.enabled` to `true`.

### 2. Create the object storage credentials

Create a bucket in your object storage, then create a Secret with credentials for it in the `controlplane` namespace. The Secret must have the keys `accessKey` and `secretKey`:

| Storage | `accessKey` | `secretKey` |
| :--- | :--- | :--- |
| Amazon S3, or any S3-compatible store | Access key ID | Secret access key |
| MinIO | Access key | Secret key |
| Azure Blob Storage | Storage account name | Storage account key |

```bash
kubectl create secret generic juicefs -n controlplane \
  --from-literal=accessKey=ACCESS_KEY \
  --from-literal=secretKey=SECRET_KEY
```

For Google Cloud Storage, create a Secret that holds a service account key file instead, and create the `juicefs` Secret with no data:

```bash
kubectl create secret generic juicefs-gcs-creds -n controlplane --from-file=credentials.json=KEY_FILE.json
kubectl create secret generic juicefs -n controlplane
```

### 3. Create the juicefs configmap

Create a ConfigMap named `juicefs` in the `controlplane` namespace:

| Key | Required | Description |
| :--- | :--- | :--- |
| `storage` | Yes | The JuiceFS storage type: `s3`, `minio`, `wasb` (Azure Blob Storage), or `gs` (Google Cloud Storage). |
| `bucket` | Yes | The bucket endpoint, in the format JuiceFS expects for that storage type. See the examples below. |
| `metadataUrl` | Yes | The metadata engine URL. Use the bundled Redis from step 1, or your own Redis or PostgreSQL. It must not have a query string, because Control Plane appends a separate `?prefix=` for each volume set. |
| `secretName` | Yes | The name of the Secret from step 2. |
| `gcsCredsSecretName` | For `gs` | The name of the Secret that holds the service account key file. |
| `gcsCredsFileName` | No | The key file's name in that Secret. Defaults to `credentials.json`. |
| `gcsCredsPath` | No | Where the key file is mounted. Defaults to `/root/.config/gcloud`. |
| `envs` | No | A JSON object of extra environment variables for JuiceFS, such as `{"AWS_DEFAULT_REGION": "us-east-1"}` for an S3-compatible store that needs a region. |

The bundled Redis Sentinel from step 1 has this `metadataUrl`:

```text
redis://juicefs-redis,juicefs-redis-sentinel-0.juicefs-redis-sentinel.juicefs,juicefs-redis-sentinel-1.juicefs-redis-sentinel.juicefs,juicefs-redis-sentinel-2.juicefs-redis-sentinel.juicefs:26379/1
```

### 4. Verify

Create a volume set with `fileSystemType: shared` in a GVC that includes the BYOK location, and mount it in a workload. The actuator formats the volume set's file system the first time it is used, and logs `Formatted the filesystem for volume set NAME`.

If the ConfigMap is incomplete, the actuator logs which key is missing, for example `JuiceFS configmap is missing required field "metadataUrl"`. If the Secret is missing `accessKey` or `secretKey`, the volume set isn't formatted and the workload's pods wait for their volume.
