## Overview

Map your own domain to your workload in about 15 minutes, plus DNS propagation time: verify your apex domain, route a subdomain to the workload, and get TLS certificates issued and renewed automatically.

**What you'll build:**

- Your apex domain (`example.com`) verified with Control Plane.
- A subdomain (`app.example.com`) routing to the `hello-world` workload.
- Automatic TLS with geo-routed global load balancing.

## Prerequisites

- Completed [1. Deploy your first workload](/quickstart/quick-start-1-deploy-workload) with the `hello-world` workload running.
- A domain name you own, with access to its DNS settings.

<Note>
This quickstart uses `example.com` as the example domain. Replace it with your own domain throughout.
</Note>

## Step 1: Register your apex domain

An apex domain (`example.com`) must be verified before creating subdomains. Even if you only use subdomains, verify the apex first.

<Steps>

<Step title="Create the apex domain">
Click `Domains` in the left menu, then click `New`. Click `Advanced`, then enter your apex domain (`example.com`).
</Step>

<Step title="Verify domain ownership">
Add the displayed TXT record to your DNS provider and wait a few minutes for propagation.
</Step>

<Step title="Set the routing mode to None">
Scroll down to `Routing Mode` and select `None`; the apex domain is only being verified, not routed.
</Step>

<Step title="Create the domain">
Click `Create`.
</Step>

</Steps>

<Tip>Create the apex domain in your production org as a best practice.</Tip>

## Step 2: Configure your subdomain

Route a subdomain (`app.example.com`) to your workload.

<Steps>

<Step title="Create the subdomain">
Click `Domains`, then `New`. Enter `app.example.com`.
</Step>

<Step title="Select the workload">
Select the `hello-world` workload from the `quickstart-gvc` GVC.
</Step>

<Step title="Configure DNS">
Add the displayed CNAME record to your DNS provider.
</Step>

<Step title="Create the subdomain">
Once the DNS record is configured, click `Create`.
</Step>

</Steps>

<Note>
Control Plane provisions TLS certificates automatically after the DNS propagates and your workload is ready. This can take a few minutes.
</Note>

<Tab title="CLI">

## Step 1: Register your apex domain

Attempt to create the apex domain:

```bash
cpln domain create --name example.com
```

The command returns an error listing the TXT records that prove ownership. Add one of them to your DNS provider, wait a few minutes for propagation, then run the command again:

```bash
cpln domain create --name example.com
```

Once ownership is verified, the domain is created.

## Step 2: Create the domain configuration

Create `domain.yaml` with the subdomain configuration:

```yaml
kind: domain
name: app.example.com
spec:
  dnsMode: cname
  ports:
    - number: 443
      protocol: http2
      routes:
        - prefix: /
          workloadLink: //gvc/quickstart-gvc/workload/hello-world
```

Apply the configuration:

```bash
cpln apply -f domain.yaml
```

## Step 3: Configure DNS

Get the GVC alias:

```bash
cpln gvc get quickstart-gvc -o yaml
```

Find the `alias` field in the output:

```yaml
alias: abc123xyz
```

Add a CNAME record to your DNS provider, replacing `abc123xyz` with your alias:

| Type  | Host | Value                  | TTL |
| ----- | ---- | ---------------------- | --- |
| CNAME | app  | `abc123xyz.t.cpln.app` | 300 |

## Step 1: Define the apex domain

Add the following to your `main.tf` to verify domain ownership:

```hcl
resource "cpln_domain" "apex" {
  name        = "example.com"
  description = "Apex domain for verification"

  spec {
    dns_mode = "cname"

    ports {
      number   = 443
      protocol = "http2"

      tls {}
    }
  }
}
```

Apply the configuration to retrieve the TXT records:

```bash
terraform apply
```

The output lists the TXT record that proves ownership. Add it to your DNS provider, wait a few minutes for propagation, then run `terraform apply` again to create the domain.

## Step 2: Define the subdomain and route

Add the subdomain and routing configuration:

```hcl
resource "cpln_domain" "app" {
  depends_on  = [cpln_domain.apex]
  name        = "app.example.com"
  description = "Application domain"

  spec {
    dns_mode = "cname"

    ports {
      number   = 443
      protocol = "http2"

      tls {}
    }
  }
}

resource "cpln_domain_route" "route" {
  depends_on = [cpln_domain.app]

  domain_link   = cpln_domain.app.self_link
  domain_port   = 443
  prefix        = "/"
  workload_link = cpln_workload.hello_world.self_link
}

output "domain_endpoint" {
  value = "https://app.example.com"
}

output "dns_cname_record" {
  value = "Type: CNAME | Host: app | Value: ${cpln_gvc.quickstart.alias}.t.cpln.app | TTL: 300"
}
```

## Step 3: Apply and configure DNS

```bash
terraform apply
```

The `dns_cname_record` output shows the CNAME record to add to your DNS provider; its value has the form `<gvcAlias>.t.cpln.app`.

  name: "app.example.com",
  description: "Application domain",
  spec: {
    dnsMode: "cname",
    ports: [
      {
        number: 443,
        protocol: "http2",
        tls: {},
      },
    ],

  domainPort: 443,

## Routing modes

Control Plane supports two routing modes:

| Mode | DNS record | Best for |
| ---- | ---------- | -------- |
| **Path-based** | CNAME | Multiple workloads on different paths (`/api`, `/web`) |
| **Subdomain-based** | NS | A unique subdomain per workload (`api.app.example.com`) |

<AccordionGroup>

<Accordion title="Path-based routing examples">

Route different paths to different workloads:

- `https://app.example.com/api` routes to the API workload.
- `https://app.example.com/web` routes to the frontend workload.
- `https://app.example.com/` routes to the default workload.

</Accordion>

<Accordion title="Subdomain-based routing examples">

Each workload receives its own subdomain automatically:

- `https://api.app.example.com` routes to the API workload.
- `https://web.app.example.com` routes to the frontend workload.

Requires NS record delegation to Control Plane.

</Accordion>

</AccordionGroup>
