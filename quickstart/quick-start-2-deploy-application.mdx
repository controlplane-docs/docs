## Overview

Build and deploy your own application to Control Plane in about 10 minutes: containerize a sample Node.js application, push it to your org's private image registry, and run it as a workload.

**What you'll build:**

- A container image of a sample Node.js application, built with Buildpacks (no Dockerfile needed).
- The image stored in your org's private registry.
- A workload running that image behind a public endpoint.

## Prerequisites

- Completed [1. Deploy your first workload](/quickstart/quick-start-1-deploy-workload), or an existing [org](/reference/org) with a [GVC](/reference/gvc).
- [Docker](https://www.docker.com/get-started) installed and running (or build remotely with the `--remote` flag in step 4).

## Step 4: Build and push the image

Build and push the image to your org's private registry:

```bash
cpln image build --name my-app:1.0 --push
```

<Tip>
`cpln image build` uses [Buildpacks](https://buildpacks.io) to detect your application type and build the image; no Dockerfile is required. If the application has a Dockerfile, the command uses that instead.

This build runs through Docker on your machine. Without Docker, replace `--push` with `--remote` to build remotely; the image is pushed for you.
</Tip>

The image is now available in your org's private registry as `//image/my-app:1.0`.

## Step 5: Create the workload

<Steps>

<Step title="Navigate to Workloads">
Click `Workloads` in the left menu, then click `New`.
</Step>

<Step title="Configure basic settings">
Enter `my-app` as the name and select `quickstart-gvc` from the GVC dropdown.
</Step>

<Step title="Configure the container">
Click `Containers` in the left pane and select `Control Plane` as the image source. In the image dropdown, type `my-app` and select `my-app:1.0`. Under `Ports`, set protocol `http` and number `8080`.
</Step>

<Step title="Configure the firewall and create">
Click `Firewall` in the left pane, click `Make Public`, then click `Create`.
</Step>

</Steps>

<Steps>

</Step>

## Step 5: Create the workload

If you completed part 1, use the existing GVC:

```bash
cpln workload create --name my-app \
  --image //image/my-app:1.0 \
  --gvc quickstart-gvc \
  --port 8080 \
  --public
```

<Note>
The `//image/` prefix tells Control Plane to pull the image from your org's private registry.
</Note>

## Step 6: Access your application

Wait for the workload to become ready:

```bash
cpln workload get my-app --gvc quickstart-gvc
```

When the `READY` column shows `true`, open the application:

```bash
cpln workload open my-app --gvc quickstart-gvc
```

## Step 5: Define the workload

Add to your existing `main.tf` from part 1:

```hcl
resource "cpln_workload" "my_app" {
  gvc  = cpln_gvc.quickstart.name
  name = "my-app"
  type = "standard"

  container {
    name   = "main"
    image  = "/org/my-org/image/my-app:1.0"
    cpu    = "50m"
    memory = "128Mi"

    ports {
      protocol = "http"
      number   = 8080
    }
  }

  options {
    capacity_ai     = true
    timeout_seconds = 5

    autoscaling {
      metric    = "disabled"
      target    = 95
      min_scale = 1
      max_scale = 1
    }
  }

  firewall_spec {
    external {
      inbound_allow_cidr = ["0.0.0.0/0"]
    }
  }
}

output "my_app_endpoint" {
  value = cpln_workload.my_app.status[0].canonical_endpoint
}
```

<Note>
Replace `my-org` with your org name; Terraform needs the full image path.
</Note>

Apply the configuration:

```bash
terraform apply
```

## Verify

Within 2 minutes of creation, the workload reports `Ready`. Open its canonical endpoint; the page lists the runtime environment variables Control Plane injects, including `CPLN_PROVIDER` and `CPLN_LOCATION` for the location that served your request.

<Check>
Your own image is in the org's private registry and running as a globally distributed workload.
</Check>

## Updating your application

To deploy a new version, update your code and build with a new image tag:

```bash
cpln image build --name my-app:1.1 --push
```

Then update your workload to use the new image:

<Tabs>

<Tab title="Console">
Navigate to your workload, click `Containers`, select the new tag, and click `Update`.
</Tab>

<Tab title="CLI">

```bash
cpln workload update my-app --gvc quickstart-gvc --set spec.containers.my-app.image=//image/my-app:1.1
```

</Tab>

<Tab title="Terraform">
Update the `image` attribute in your Terraform configuration and run `terraform apply`.
</Tab>

<Tab title="Pulumi">
Update the `image` property in your Pulumi code and run `pulumi up`.
</Tab>

</Tabs>

## What you've learned

- **Private registry**: your images are stored within your org.
- **Image references**: the `//image/` prefix for the CLI, the full `/org/<org>/image/` path for IaC tools.
- **Buildpacks**: `cpln image build` containerizes your application without a Dockerfile.
- **Environment variables**: Control Plane injects `CPLN_LOCATION`, `CPLN_PROVIDER`, and other `CPLN_*` variables automatically.

To delete just the `my-app` workload created in this part:

<Tabs>

<Tab title="Console">

</Tab>

```bash
cpln workload delete my-app --gvc quickstart-gvc
```

</Tab>

<Tab title="Terraform">

Remove the `cpln_workload.my_app` resource from your `main.tf` and run:


</Tab>

<Tab title="Pulumi">

Remove the `my-app` workload from your code and run:

```bash
pulumi up
```

</Tab>

<Note>
To delete images, navigate to `Images` in the Console, select the image name, and from `Actions` click `Delete` to remove all tags. With the CLI, delete each tag individually: `cpln image delete my-app:1.0`.
</Note>
