## Overview

Connect two workloads over Control Plane's internal network in about 10 minutes: deploy a caller workload, watch the default deny block its request, then allow same-GVC traffic and verify the call succeeds. Internal traffic is encrypted with mTLS automatically; no certificate management is required.

**What you'll build:**

- A `caller` workload that makes requests to the `hello-world` workload.
- A firewall rule on `hello-world` allowing internal traffic from the same GVC.
- An encrypted service-to-service call you can observe end to end.

## Prerequisites

- Completed [1. Deploy your first workload](/quickstart/quick-start-1-deploy-workload) with the `hello-world` workload running.
- Permission to create workloads in your org, granted via [policies](/guides/policy).

## How internal communication works

Workloads communicate using internal endpoints that follow this pattern:

```text
http://WORKLOAD_NAME.GVC_NAME.cpln.local:PORT
```

By default, workloads are isolated and reject internal traffic; firewall rules control which workloads may communicate.

## Step 1: Create the caller workload

<Steps>

<Step title="Navigate to Workloads">
Click `Workloads` in the left menu, then click `New`.
</Step>

<Step title="Configure basic settings">
Enter `caller` as the name and confirm the GVC dropdown shows `quickstart-gvc`.
</Step>

<Step title="Configure the container">
Click `Containers` in the left pane and select `External` as the image source. Enter the image `cplnquickstarts/service-to-service-quick-start:1.1`. Under `Ports`, set protocol `http` and number `8080`.
</Step>

<Step title="Configure the firewall and create">
Click `Firewall` in the left pane, click `Make Public`, then click `Create`.
</Step>

</Steps>

## Step 2: Test the default deny

<Steps>

<Step title="Open the caller workload">
When the `caller` workload health shows `Ready`, open the link next to `Canonical Endpoint (Global)` on its summary page.
</Step>

<Step title="Make an internal call">
Add this query parameter to the caller URL:

```text
?url=http://hello-world.quickstart-gvc.cpln.local:8080
```

The request times out: the `hello-world` workload blocks internal traffic by default.
</Step>

</Steps>

## Step 3: Allow internal traffic

<Steps>

<Step title="Open the hello-world firewall">
Click `Workloads` in the left menu, select `hello-world`, then click `Firewall` in the left pane.
</Step>

<Step title="Allow same-GVC traffic">
Under the `Internal` tab, select `Same GVC` for the `Inbound Allow Type`, then click `Update`.
</Step>

</Steps>

<Tab title="CLI">

## Step 1: Create the caller workload

```bash
cpln workload create --name caller --gvc quickstart-gvc \
  --image cplnquickstarts/service-to-service-quick-start:1.1 \
  --port 8080 \
  --public
```

## Step 2: Test the default deny

Get the caller endpoint:

```bash
cpln workload get caller --gvc quickstart-gvc
```

Open the endpoint from the output in your browser and add:

```text
?url=http://hello-world.quickstart-gvc.cpln.local:8080
```

The request times out: the `hello-world` workload blocks internal traffic by default.

## Step 3: Allow internal traffic

Update the `hello-world` firewall to allow traffic from the same GVC:

```bash
cpln workload update hello-world --gvc quickstart-gvc --set spec.firewallConfig.internal.inboundAllowType=same-gvc
```

## Step 1: Add the caller workload

Add to your existing `main.tf` from part 1:

```hcl
# Caller workload
resource "cpln_workload" "caller" {
  gvc  = cpln_gvc.quickstart.name
  name = "caller"
  type = "standard"

  container {
    name   = "main"
    image  = "cplnquickstarts/service-to-service-quick-start:1.1"
    cpu    = "50m"
    memory = "128Mi"

    ports {
      protocol = "http"
      number   = 8080
    }
  }

  options {
    capacity_ai     = true
    timeout_seconds = 5

    autoscaling {
      metric      = "disabled"
      target      = 95
      min_scale   = 1
      max_scale   = 1
    }
  }

  firewall_spec {
    external {
      inbound_allow_cidr = ["0.0.0.0/0"]
    }
  }
}

output "caller_endpoint" {
  value = cpln_workload.caller.status[0].canonical_endpoint
}
```

Apply the configuration:

```bash
terraform apply
```

## Step 2: Test the default deny

Open the caller endpoint (the `caller_endpoint` output) in your browser and add:

```text
?url=http://hello-world.quickstart-gvc.cpln.local:8080
```

The request times out: the `hello-world` workload blocks internal traffic by default.

## Step 3: Allow internal traffic

Update your `cpln_workload.hello_world` resource. Add the `internal` block inside `firewall_spec`:

```hcl
firewall_spec {
  external {
    inbound_allow_cidr  = ["0.0.0.0/0"]
  }

  # Add internal firewall to allow traffic from same GVC
  internal {
    inbound_allow_type = "same-gvc"
  }
}
```

Apply the changes:

```bash
terraform apply
```

## Verify

Within 2 minutes of the firewall update, the `hello-world` workload redeploys with the new rules. Refresh the caller page with the `?url=` parameter; the response now comes from `hello-world`:

```text
Response from URL:

---
Hello World!
---
```

<Check>
Two workloads communicate over the internal network, encrypted with mTLS, with access controlled by the workload firewall.
</Check>

## Internal firewall options

| Value | Behavior |
| ----- | -------- |
| `none` (default) | No internal access to this workload |
| `same-gvc` | Any workload in the same GVC may access it |
| `same-org` | Any workload in the org may access it |
| `workload-list` | Only the workloads listed in `inboundAllowWorkload` may access it |

<Note>
The `workload-list` option requires `view` permission on the allowed workloads.
</Note>

## Internal endpoint format

Workloads communicate using internal DNS endpoints:

```text
http://WORKLOAD.GVC.cpln.local:PORT
```

**Examples:**

- `http://api.production-gvc.cpln.local:8080`
- `http://cache.quickstart-gvc.cpln.local:6379`

<Note>The endpoint above load-balances across all replicas. For stateful workloads with `replicaDirect` enabled, you can also reach an individual replica directly; see [Finding Replica Hostnames](/reference/workload/general#finding-replica-hostnames).</Note>

## What you've learned

- **Isolated by default**: workloads block internal traffic until a firewall rule allows it.
- **Automatic mTLS**: internal traffic is encrypted without certificate configuration.
- **Firewall rules** control which workloads may communicate.
- **Internal endpoints** use the `.cpln.local` domain.
